# Три траектории решения задачи о шинных смесях

Задача у всех одна: по 3774 патентным рецептурам и опубликованным методам предсказать свойства шинной смеси и предложить рецептуры под заданные свойства. Три решения: ручная работа Наргизы (август–сентябрь 2026, репозиторий `Naramerk/tires`), coding-агент opencode на GLM-5.3 (`runs/baseline-opencode/`), CoScientist на GLM-5.3 (`runs/tyre-main-2_*`).

## Сводка

| | Наргиза | opencode | CoScientist |
|---|---|---|---|
| Время, стоимость | недели, — | 60 мин, 6,3 $ | 105 мин, 3,4 $ |
| Данные | собрала сама, обогатила справочниками марок | взял, почистил, нашёл дубликаты | взял как есть |
| Методы | 3 воспроизведены на данных авторов | 2 запущены, обзор 9 работ | 4 запущены, найдены веса Wan |
| Модели | каскад XGBoost по стадиям, TVAE, Optuna | 5 моделей × 12 свойств, permutation importance | XGBoost на 733 признаках, тест Уилкоксона |
| Проверка | группы по хэшу рецептуры | случайная и по патентам | случайная, отложенные патенты, группы по патентам |
| R² Муни, случайная / по патентам | 0,73 / −0,01¹ | 0,78 / 0,06 | 0,8 / −0,28 |
| R² M300, случайная / по патентам | 0,78 / 0,28¹ | 0,87 / 0,39 | 0,9 / 0,0 |
| Обратная задача | нет | 66 тыс. кандидатов, 3 оценки доверия | NSGA-II, 120 тыс. оценок, покрытие интервалов |
| Вывод о переносе на новые патенты | не проверяла | нет переноса, кроме M300 | нет переноса |
| Что осталось | репозиторий, датасет, справочники | скрипты, клоны, отчёт | граф, сессия, серверы в каталоге |

¹ Первое число из её отчёта (группы по хэшу рецептуры, по смыслу это случайное разбиение). Второе число это наша переоценка на её очищенном датасете с группами по патенту.

**Общий вывод.** Как только проверка честная, все три приходят к одному: по открытым патентным данным свойства новой рецептуры не предсказываются, кроме слабого сигнала по M300. Наргиза дала лучшие данные и инженерную конструкцию, opencode дал самый глубокий разбор самих данных, CoScientist дал тот же вывод в форме, которую можно проверить по графу и продолжить с готовых инструментов.

**Как читать R².** R² = 1 точный прогноз, R² = 0 модель не лучше среднего по всем смесям, R² < 0 модель хуже среднего. «Случайная» проверка делит строки случайно, и соседние смеси из одного патента попадают по обе стороны. «По патентам» откладывает целые патенты, и модель не видела ни одной смеси из них. Только второй вариант отвечает на вопрос «предскажем ли мы рецептуру нового производителя». Различия между 0,0, 0,28 и 0,39 по патентам частично объясняются разными признаками и моделями и не означают победы одного метода.

## 1. Наргиза, ручная работа

**Данные.** Сама построила датасет: скрипт поиска патентов на Google Patents, извлечение рецептур и свойств из текста патентов через LLM, очистка (сумма каучуков ровно 100 phr, выбросы по IQR), справочники марок сырья с физико-химическими свойствами сажи, кремнезёма и полимеров. Отдельно посчитала pSMILES каучуков с учётом микроструктуры и дескрипторы RDKit.

**Исследование методов.** Разобрала около 10 репозиториев. Оставила три, где есть код и данные авторов: PolymerGNN (воспроизвела R² 0,86 на полиэфирах Eastman), Sty-GTR (модификация резиновой крошки стиролом, 69 опытов, R² 0,93), Wan MT-DNN (восстановила архитектуру из весов). TransPolymer отбросила из-за несовместимости версий transformers, второй репозиторий Wan отбросила как дубликат.

**Модели.** Каскад из трёх XGBoost по стадиям производства: смешение → Муни, вулканизация → t90 и ts2, вулканизат → M300, прочность, твёрдость. Прогноз предыдущей ступени идёт входом следующей. Плюс подбор гиперпараметров Optuna, аугментация синтетических рецептур через TVAE, адаптации Wan MT-DNN, PolymerGNN и polyBERT с 29 свойствами Polymer Genome под шинные данные.

**Проверка.** GroupKFold, группы по хэшу точной рецептуры (phr, дескрипторы, процесс).

**Результат.** R² 0,73 по Муни, 0,78 по M300, 0,51 по t90. Внешние модели хуже каскада: Wan MT-DNN 0,48 по Муни, PolymerGNN 0,38, polyBERT прироста не даёт.

**Как интерпретировать.** Самая полная инженерная работа из трёх: свой датасет, свои справочники, каскад по физике процесса. Но цифры качества относятся к вопросу «предскажем ли мы соседнюю рецептуру из знакомого патента». Группировка по хэшу держит вместе только полностью одинаковые строки, а почти одинаковые из одного патента расходятся по обучению и тесту. При проверке по патентам та же модель на её данных даёт −0,01 по Муни, 0,28 по M300, −0,23 по t90. Переноса на новую рецептуру у каскада нет, но сама она этого не увидела, потому что проверка была недостаточно строгой.

## 2. opencode, coding-агент на GLM-5.3

**Исследование методов.** Через 25 веб-запросов разобрал все 9 работ из промпта: что предсказывает, как кодирует состав, есть ли код, веса, данные. Сам заметил, что официальный репозиторий polyBERT пуст и код выдают по запросу. Wan не нашёл, потому что искал по названию статьи.

**Библиотеки.** pandas, scikit-learn, torch CPU, transformers 5.x, sentence-transformers. Для TransPolymer переписал токенизатор, потому что исходный класс не импортируется на новой transformers.

**Данные.** Взял датасет как есть, почистил физически невозможные значения (Муни 0, tan δ 141, прочность 162 МПа). Посчитал, что 2668 из 3774 строк повторяют рецептуру другой строки, а 1400 идентичны по всем признакам. Исключил из признаков QC-колонки, заметив, что датасет собран LLM-парсером.

**Эксперименты.** 8 скриптов: 12 свойств × 5 моделей (dummy, ridge, PLS, RF, HistGB) × 2 разбиения (случайное и по патентам). Сравнение представлений: phr, phr без эластомерных колонок, plus polyBERT, plus TransPolymer. Permutation importance. Обратная задача: 66 тыс. случайных кандидатов, фильтр по целевому окну и расстоянию до обучающих данных, кластеризация для разнообразия.

**Результат.** По патентам Муни 0,06, M300 0,39, остальные около нуля или ниже. Эмбеддинги для M300 дают тот же уровень, что phr, для Муни ничего. Собственная находка: главный признак Муни это `elastomer_mooney_raw`, измеренная вязкость сырого каучука, которой на этапе проектирования ещё нет. Исключил её из обратной задачи и получил Муни −0,18.

**Как интерпретировать.** Самый глубокий анализ данных из трёх. Агент сразу выбрал честную проверку и объяснил, почему случайная обманывает. Слабые места: не нашёл репозиторий с весами Wan, PolymerGNN не запустил (нет геометрий мономеров). Кэш промптов не работал, поэтому вдвое дороже CoScientist. После него осталась папка со скриптами, клонами и отчётом на одной машине; переписанный токенизатор остался файлом в папке.

## 3. CoScientist на GLM-5.3

**Постановка.** ContextInit превратил промпт в рамку исследования. HypothesesAgent выдвинул 6 гипотез с критериями подтверждения: H1 доступность методов, H2 польза представлений, H3 обратная задача, H4–H6 в бэклог (физические признаки, дообучение языковых моделей, генеративная модель рецептур).

**Исследование методов (H1, 17 минут).** Кодер установил и запустил каждый метод минимальным скриптом: `polybert_minimal.py`, `transpolymer_minimal.py`, `polymergnn_minimal.py`, `wan_minimal.py`. Ставил torch CPU, transformers (перебрал 4.30, 4.36 и текущую), torch_geometric 2.5.3, tensorflow-cpu, rdkit. Сам нашёл репозиторий `Vanguer/rubber-mechanical-properties-prediction` с 7 весами `.h5` и запустил их. PolymerGNN обучил 2 эпохи. Вердикт: работают 4 из 7. Литературный агент в этом прогоне не участвовал.

**Эксперименты (H2, около 60 минут).** XGBoost и LightGBM на 733 признаках (phr, one-hot марок, процесс). Три протокола: случайное разбиение, отложенные патенты, групповая кросс-валидация по патентам. Признаки: phr против phr плюс polyBERT, TransPolymer, Wan. Парный тест Уилкоксона на значимость.

**Обратная задача (H3, около 20 минут).** NSGA-II из pymoo поверх ансамбля 5 XGBoost, 120 тыс. оценок, 5 рецептур с интервалами, проверка покрытия интервалов.

**Результат.** H1 подтверждена, H2 опровергнута (по патентам Муни −0,28, M300 около 0, эмбеддинги не помогают при p 0,28 и 0,31), H3 без вывода: 5 рецептур формально в окне, но покрытие интервалов 0,39. Причина утечки названа: one-hot марок кодирует семейства патентов.

**Что было потом.** По одной просьбе в конце сессии агент собрал через Alembic два сервера: Wan (4 инструмента) и TransPolymer (5 инструментов), все инструменты прошли тесты и живые вызовы. Отдельная сессия получила прогноз прочности и удлинения для рецептуры через сервер Wan за 4 минуты и 0,14 $ без установки.

**Как интерпретировать.** По анализу данных сопоставимо с opencode, местами слабее (не нашёл признак-измерение), местами сильнее (проверка методов запуском, найденные веса Wan, тест значимости, оценка покрытия интервалов). Отличие в форме результата: гипотезы с вердиктами в графе, отчёт, где каждое утверждение привязано к узлу, экспорт сессии, серверы в каталоге.

## Что значит отрицательный результат

Цель «спроектировать рецептуру по открытым данным» не достигнута ни одним из трёх, и это свойство данных, а не ошибка систем. Дальше нужны другие данные (измерения свойств сырья, данные производителей) или лабораторная проверка кандидатов, то есть участие человека. Все скрипты, серверы и граф для этого сохранены.
