План работ по проекту
Цели и ожидаемые результаты
Конечная цель проекта - построение иерархического каскада из трёх моделей, описывающих последовательные стадии производства резиновой смеси: смешение, вулканизация, испытания вулканизата. Каждая модель решает прямую задачу (forward): по заданным входным условиям предсказывает измеряемые свойства.
Каскад моделей сокращает число итераций «синтез - испытание» в цикле разработки рецептуры, заменяет часть дорогих лабораторных тестов (DMA, износ) прогнозом по дешёвым (Mooney, реометрия), даёт химически осмысленные объяснения (SHAP) и закладывает основу для следующей фазы - обратной задачи (inverse), то есть автоматизированного поиска рецептуры по заданному балансу свойств. Без качественного предиктора и обогащённого датасета inverse-задача невозможна.
Ключевое ограничение проекта. Малое число исторических рецептур. Это требует особого подхода к feature engineering (использование физико-химических дескрипторов сырья, химической структуры компонентов через SMILES) и обогащению датасета (transfer learning, аугментация через генеративные модели с лабораторной валидацией).

Этап 1. Анализ данных и проверка гипотез
Длительность: 3 месяца (месяцы 1–3)
1.1. Цели этапа
* Получить полную картину доступных данных на всех трёх стадиях производства (входной контроль, смешение, вулканизация) и оценить их пригодность для построения ML-моделей.
* Проверить, можно ли использовать результаты физико-химических тестов входного контроля в качестве дескрипторов компонентов для модели - это базовая гипотеза проекта, и её подтверждение или опровержение определяет архитектуру дальнейших работ.
* Сравнить несколько подходов к представлению химической информации о компонентах (RDKit-дескрипторы, фингерпринты, графовые представления, эмбеддинги из предобученных моделей) и выбрать оптимальный для данных заказчика.
* Построить первые базовые ML-модели каждой ступени каскада и зафиксировать baseline-метрики для дальнейшего сравнения.
* Провести поиск и анализ существующих работ и открытых датасетов для усиления имеющегося набора данных для обучения моделей, и поиска дополнительных алгоритмов для анализа резиновой смеси.
1.2. Активности и результаты по месяцам
Месяц 1. Аудит данных
Активности:
* Интервью с технологами входного контроля, операторами смешения и лабораторией: что и как измеряется на каждом этапе, в каком виде хранится, как часто.
* Инвентаризация источников: журналы входного контроля сырья, журналы смешения (параметры режима, замеры после смешения), журналы вулканизации, протоколы испытаний вулканизата.
* Сбор первого среза данных (пилотная выборка) с привязкой каждой рецептуры к партиям использованного сырья и параметрам процесса.
* Анализ полноты данных: для каких компонентов есть физико-химические дескрипторы из входного контроля, для каких - только паспортные данные поставщика, для каких - ничего.
* Анализ открытых расчетных моделей и источников данных, их пригодности для рассматриваемой задачи. Оценка существующих открытых научных статей, содержащих открытые данные о рецептурах и расчетные алгоритмы, предназначенные для оценки физических и химических свойств резиновой смеси. Согласование с заказчиком актуальности найденных открытых данных.
Результаты месяца:
* Карта данных: схема всех источников и связей между ними; оценка реального объёма пилотной выборки.
* Подтверждённый или опровергнутый ответ на ключевой вопрос: на каких стадиях процесса дескрипторы из входного контроля доступны и регулярно регистрируются.
* Список существующих открытых данных, статей и алгоритмов с пометкой об их пригодности для использования в текущем проекте.
* Согласованный с заказчиком список приоритетных свойств для предсказания на каждой стадии.
Месяц 2. Feature engineering и базовые модели
Сравнение способов представления компонентов. Для каждого компонента рецептуры химическая информация может быть закодирована несколькими способами. Каждый из них передаёт модели разный уровень понимания химии:


Способ
	Что это технически
	Что «понимает» модель
	Состав в phr
	Одно число на компонент
	Только количество. Новый компонент = новая колонка, нет обобщения
	Физико-химические дескрипторы партий
	Параметры из входного контроля 
	Различия между партиями одного компонента - учитывает реальную вариабельность сырья
	RDKit-дескрипторы
	~200 численных характеристик молекулы (масса, число атомов S, полярность и т.д.)
	Общую химическую природу молекулы. Похожие молекулы дают похожие дескрипторы
	Морган-фингерпринты
	Бинарный вектор длиной 1024 или 2048; каждый бит - наличие подструктуры (функциональной группы). 
	Конкретные фрагменты молекулы (тетрасульфидный мостик, ароматическое кольцо). 
	Графовое представление (GNN)
	Молекула как граф: атомы - узлы, связи - рёбра
	Полную структуру и топологию. Может оценить молекулу, которой не было в обучении
	Эмбеддинги из предобученных моделей
	Сжатый вектор от модели (PolyBERT, ChemBERTa), обученной на миллионах молекул
	Накопленные знания о химии полимеров. Лучший перенос на новые компоненты
	

Все способы передают модели «химизм», но разной глубины. RDKit-дескрипторы - это быстрая и надёжная базовая линия. Фингерпринты и графовые представления требуют чуть больше данных, но дают способность к обобщению на новые компоненты - критически важную при работе с функционализированными полимерами от новых поставщиков.
Активности:
* Описательная статистика по собранным данным: распределения свойств, корреляции, обнаружение явных выбросов.
* Сбор SMILES для компонентов рецептур, имеющих известную структуру (силаны, ускорители, антиоксиданты, каучуки через pSMILES).
* Реализация четырёх вариантов feature engineering для базовой модели: (а) только phr, (б) phr + дескрипторы партий, (в) phr + дескрипторы партий + RDKit, (г) то же + Морган-фингерпринты.
* Обучение базовых ML-моделей для трёх ступеней каскада (XGBoost / LightGBM): модель 1 - смешение (вход: сырьё + режим - выход: Mooney сырой смеси, дисперсия); модель 2 - вулканизация (вход:  рецептура сырой смеси + режим вулканизации - выход: реометрия - ts2, t90, MH, ML); модель 3 - вулканизат (вход: реометрия + рецептура - выход: прочность, удлинение, твёрдость).
* Применение SHAP-анализа к каждой ступени: какие фичи реально работают, какие шумят, согласуются ли вклады с химической интуицией.
* Провести анализ возможной имплементации расчетных методов и алгоритмов для расчет физико-химических свойств резиновой смеси.
* Анализ существующих нейросетевых моделей (MLP, attention-based, GNN, VAE) предназначенные для задач генерации резиновых смесей и оценки их свойств.
* Анализ имеющегося объема открытых данных, потребность в их быстром анализе используя LLM, оценка возможности и целесообразности разработки RAG системы на основе векторной базы данных.
Результаты месяца:
* Зафиксированные baseline-метрики (R², MAE) по каждой ступени каскада и каждому варианту feature engineering.
* Количественный ответ: какой способ представления компонентов даёт наибольший прирост точности на данных заказчика.
* Анализ возможности и необходимости разработки и имплементации расчетных моделей для оценки свойств резиновой смеси и RAG системы.
* Анализ применимости нейросетевых моделей для текущих задач.
* Первичный SHAP-отчёт с экспертной валидацией химиков.
Месяц 3. Проверка гипотез и архитектурные решения
Гипотезы к проверке:
* Дескрипторы сырья из входного контроля повышают точность модели на ≥3% R² по сравнению с моделью только на phr.
* Каскадная архитектура (3 модели) даёт лучшие результаты, чем монолитная модель «состав - конечное свойство», за счёт использования промежуточных измерений как фичей.
* Молекулярные представления (RDKit / фингерпринты / эмбеддинги) повышают точность для рецептур, содержащих новые или редко встречающиеся компоненты.
* В исторических данных есть систематические выбросы (5–10%); их удаление повышает точность сильнее, чем смена алгоритма.
* Проверка возможности расчета целевых свойств найденными расчетными методами и алгоритмами.
Активности:
* Эксперименты по каждой гипотезе с фиксацией дельты метрик.
* Анализ остатков базовых моделей: где модель промахивается чаще всего, какие компоненты или режимы недопредставлены.
* Подготовка дорожной карты для этапа 2: какие усложнения архитектуры оправданы, какие гипотезы переносятся, какие отбрасываются.
Результаты этапа 1:
* Технический отчёт по проверке гипотез с количественными результатами.
* Финализированная архитектура каскада с выбранным способом feature engineering.
* Baseline-модели всех трёх ступеней с метриками.
* Контрольная точка с заказчиком (Gate 1): принятие архитектуры и переход на этап 2 или корректировка плана.
Этап 2. Разработка моделей, обогащение датасета, апробация
Длительность: 3 месяца (месяцы 4–6)
2.1. Цели этапа
* Перейти от базовых моделей этапа 1 к более сложным архитектурам - нейронным сетям и графовым моделям - там, где это оправдано результатами проверки гипотез.
* Разработать прототипы расчетных моделей для оценки физико-химических свойств, по результатам оценочного анализа.
* Расширить обучающую выборку через аугментацию данных с лабораторной валидацией качества синтетических точек.
* Провести апробацию каскада на стороне заказчика: предсказание свойств для рецептур, не входивших в обучение, с последующей лабораторной проверкой.
2.2. Активности и результаты по месяцам
Месяц 4. Усложнённые архитектуры моделей
Активности:
* Тестирование нейросетевых архитектур поверх каскада: полносвязные сети (MLP) для модели 1, рекуррентные или attention-based для модели 2 (последовательность стадий смешения), графовые нейросети (GNN) для модели 3 при работе с новыми компонентами.
* Применение transfer learning: использование предобученных моделей (PolyBERT, ChemBERTa) как feature extractors для эластомеров и низкомолекулярных компонентов рецептуры. Это критически важно при малом объёме данных заказчика - предобученные модели несут в себе знания о химии из миллионов сторонних молекул.
* Кросс-валидация с разбиением по семействам рецептур и по времени для проверки устойчивости моделей.
* Сравнение нейросетевых моделей с baseline (XGBoost) на одних и тех же выборках: переход на более сложную архитектуру оправдан только при значимом приросте качества.
* Разработка векторной базы данных и RAG для найденных открытых литературных данных, при необходимости аккумулировать информацию и проводить быстрый поиск при LLM.
Результаты месяца:
* Финальные версии моделей каждой ступени каскада с подтверждёнными метриками.
* Решение по архитектуре каждой ступени: какие задачи остаются на классическом ML, где переходим на нейросети или графовые модели.
Месяц 5. Обогащение датасета и лабораторная валидация
Подходы к аугментации:
* Генеративные модели (VAE). Variational Autoencoder обучается на исторических рецептурах, затем генерирует новые «правдоподобные» рецептуры в близкой к реальной области пространства составов. Свойства синтетических рецептур оцениваются через текущий каскад моделей.
* Физико-обоснованная разметка. Эмпирические правила (Fox для Tg смесей каучуков, Mark-Houwink для связи вязкости и молекулярной массы, правило смешения для модулей) используются для разметки части синтетических рецептур независимо от модели.
* Дезагрегация по партиям сырья. Каждая историческая рецептура с известными партиями компонентов раскладывается на несколько эффективных точек - это даёт обогащение датасета без какой-либо генерации.
Лабораторная валидация синтетических данных:
Ключевой этап доверия к аугментации - экспериментальная проверка качества синтетических точек.
* Из сгенерированных синтетических рецептур выбирается репрезентативная выборка (10–20 точек), покрывающая разные области пространства составов.
* Эти рецептуры изготавливаются в лаборатории заказчика и проходят полный пакет испытаний.
* Сравнение лабораторных результатов с тем, что предсказывала модель для синтетических точек, даёт оценку: можно ли доверять аугментации и в каких границах.
* По итогам валидации синтетические данные либо включаются в обучающую выборку с весом, обратно пропорциональным ошибке, либо отбрасываются как ненадёжные.
Активности:
* Реализация выбранных на этапе 1 методов аугментации; генерация расширенной выборки.
* Изготовление и испытание репрезентативной выборки в лаборатории заказчика.
* Переобучение моделей каскада на расширенном датасете с валидацией прироста точности.
* Подготовка прототипа интерфейса для технолога: ввод рецептуры + параметров - прогноз каскада с SHAP-объяснениями.
Результаты месяца:
* Расширенный датасет с подтверждённым качеством синтетических точек.
* Финальные модели каскада на расширенных данных.
* Рабочий прототип интерфейса для пользователя-технолога.
Месяц 6. Апробация на стороне заказчика
Активности:
* Совместно с технологами заказчика отбор 5–10 рецептур для слепого теста: предсказание делается моделью до изготовления и испытаний.
* Изготовление выбранных рецептур в лаборатории заказчика по стандартным протоколам; параллельно фиксируются предсказания модели для всех трёх ступеней каскада.
* Сравнение предсказаний с фактическими измерениями. Анализ ошибок: на какой ступени каскада возникают расхождения и почему.
* Экспертная оценка SHAP-объяснений технологами: насколько химически осмысленны рекомендации модели.
* Анализ окупаемости: сколько лабораторных циклов экономит каскад на типичном проекте разработки рецептуры; оценка экономии в денежном выражении.
Результаты этапа 2:
* Финальный отчёт по апробации с метриками точности на ранее не виденных рецептурах.
* Карта надёжности модели: где предсказания достаточно точны для замены лабораторного теста, где - только для ранжирования кандидатов, где модель пока не работает.
* Дорожная карта развития на следующую фазу проекта.
Итоги двух этапов и переход к обратной (inverse) задаче
Иерархический каскад из трёх моделей: смешение - вулканизация - вулканизат. Каждая модель решает прямую задачу - предсказывает измеряемые свойства на своей стадии. Каскад собран в единый pipeline и доступен через интерфейс, не требующий навыков программирования.
Почему каскад выгоден бизнесу
* Сокращение числа лабораторных итераций. Каскад forward-моделей позволяет виртуально оценить десятки вариантов и в лабораторию направить только перспективные. 
* Замена дорогих испытаний прогнозом. Дорогие тесты частично заменяются прогнозом по дешёвым. Лабораторные мощности высвобождаются для критических измерений.
* Диагностика процесса. Расхождение предсказания с реальностью на одной из ступеней каскада указывает на конкретный источник проблемы - сырьё, режим смешения или вулканизация. 
* Виртуальный скрининг новых компонентов. При работе с молекулярными представлениями (графовыми моделями, эмбеддингами) каскад может оценивать новые ингредиенты по их структуре до закупки и физических испытаний. Это особенно ценно при активном поиске функционализированных полимеров.
* Сохранение экспертизы. Модель + SHAP-объяснения фиксируют накопленные знания компании в системе. Менее опытные специалисты могут работать с моделью как с «цифровым наставником».
Что становится возможным после проекта: inverse-задача
Forward-модель отвечает на вопрос: «что получится, если смешать эти компоненты в этих условиях?». Inverse-задача - обратная: «какую рецептуру и режим нужно подобрать, чтобы получить заданные целевые свойства?».
Это принципиально другая задача - она требует поиска в многомерном пространстве рецептур с учётом одновременно нескольких целевых свойств, у которых есть компромиссы (магический треугольник: rolling resistance, wet grip, износостойкость). Решается она через многокритериальную оптимизацию: алгоритм (NSGA-II, NSGA-III или Bayesian Multi-Objective Optimization) перебирает виртуальные рецептуры, спрашивая каскад forward-моделей вместо лаборатории, и строит Pareto-фронт - карту всех оптимальных компромиссов.
Принципиально важно: inverse-задача невозможна без качественной forward-модели. Если каскад делает ошибочные предсказания, оптимизатор найдёт «оптимальные» рецептуры в виртуальном пространстве, которые в реальной лаборатории не воспроизводятся. Поэтому именно этап 1–2 текущего проекта закладывает фундамент: forward-модели нужного качества и обогащённый датасет, без которых дальнейшее движение бессмысленно.
