```bash
# Запуск из корня проекта
python CoScientist/sapphire_pipeline/__main__.py
```

1. Устанавливается блокировка от одновременного запуска, загружаются настройки из `config.env` и создаются клиенты S3, Chroma, LLM и embeddings.
2. Из выбранной коллекции Chroma читаются DOI и `article_id` уже загруженных статей для проверки дублей.
3. Из Sapphire постранично читаются записи через `GET /publications` с параметрами `limit` и `offset`. Перед обработкой каждой записи логируются её номер, OpenAlex ID и название: `[42/1000]`, если задан `--max-articles 1000`, или `[42]` без лимита. Нумерация начинается с 1 при каждом запуске и включает пропуски и ошибки; число после `/` — лимит, а не размер базы.
4. Проверяются оценки `domains`: требуется `score > 0` у `ai` или `chembio`, при этом положительная оценка `photonics` исключает статью, даже если есть AI/chembio. Нулевые оценки не считаются принадлежностью к теме. Без подходящих оценок статья пропускается с причиной `domain_filtered`; такие пропуски входят в `--max-articles`.
5. DOI статьи нормализуется и проверяется по существующим чанкам. Если статья уже есть в RAG, она пропускается.
6. Проверяется `is_open_access`. Если значение не равно `true`, статья пропускается.
7. Проверяется наличие корректного `openalex_id`. Если его нет, статья пропускается; иначе запрашивается `GET /crawler/openalex/works/{openalex_id}`.
8. Из ответа извлекаются предварительные `domain` и `field`. Если классификация отсутствует, фиксируется ошибка статьи. Если DOI ещё не известен, он берётся из ответа и повторно проверяется на дубли.
9. Собираются PDF-ссылки из записи Sapphire и доступных локаций OpenAlex. Ссылки проверяются по очереди: HTTP-статус, размер файла и сигнатура PDF. Если пригодного PDF нет, статья пропускается.
10. PDF скачивается в память, вычисляется `article_id = MD5(pdf)`. Если такой идентификатор уже есть в Chroma, статья пропускается.
11. PDF сохраняется в `S3_PUBLIC_BUCKET` по ключу `articles/{domain}/{article_id}/paper.pdf`.
12. Запускается обработка через оригинальные этапы `papers_processing_refactoring`. Используются сохранённые состояния этапов для возобновления незавершённой обработки.
13. `FetchStep` читает PDF из S3 и сохраняет рабочую копию в `S3_ETL_BUCKET`.
14. `ParseStep` преобразует PDF в HTML и изображения через Marker.
15. `HtmlCleaningStep` очищает HTML.
16. `ImageFilteringStep` фильтрует изображения и извлекает таблицы.
17. `ImageCaptioningStep` создаёт текстовые описания изображений.
18. `MetadataExtractionStep` извлекает название статьи, год, авторов и источник. Готовый DOI Sapphire используется напрямую; поиск DOI по названию и году выполняется только при его отсутствии.
19. Определяются итоговые `domain`, `field` и источник публикации через OpenAlex. Если классификация не получена, используется LLM по содержимому статьи. Суммаризация не выполняется.
20. `ChunkingStep` создаёт чанки `body` и `image_caption`. Чанки `summary` не создаются.
21. `EmbeddingStep` вычисляет векторы чанков.
22. `PublishStep` записывает чанки и векторы в Chroma. В метаданные попадают только `article_id`, `role`, `domain`, `field`, `modality`, `paper_title`, `publication_year`, `authors`, `source`, `doi`, `ingestion_source`, а также `imgs_in_chunk` для текста или `image_id` для описания изображения. Поле `ingestion_source="sapphire"` обозначает источник загрузки; остальные служебные поля Sapphire в чанки не добавляются.
23. В `S3_PUBLIC_BUCKET` публикуются PDF, HTML, изображения и `meta.json` со служебными данными статьи. Источник загрузки обозначается как `article_metadata.ingestion_source = "sapphire"`; поле `source` сохраняет название источника публикации. Используется итоговый `domain`; если он отличается от предварительного, ранее загруженная копия PDF остаётся в прежнем каталоге.
24. После успешной публикации удаляются промежуточные ETL-артефакты и проверяется наличие чанков статьи в Chroma. DOI и `article_id` добавляются в наборы проверки дублей текущего запуска.
25. Пайплайн переходит к следующей статье. Ошибка отдельной статьи фиксируется и не останавливает остальные; ошибка чтения страницы Sapphire прерывает проход.
26. Обработка завершается при пустой странице или достижении `--max-articles`. Лимит учитывает все рассмотренные записи, включая пропуски и ошибки, а не только сохранённые статьи. Без `--max-articles` читаются все страницы. Выводятся количество просмотренных и загруженных статей, причины пропусков и число ошибок.
