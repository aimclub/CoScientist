```bash
# Запуск из корня проекта
python CoScientist/sapphire_pipeline/__main__.py
```

1. Устанавливается блокировка от одновременного запуска, загружаются настройки из `config.env` и создаются клиенты S3, Chroma, LLM и embeddings.
2. Из выбранной коллекции Chroma читаются DOI и `article_id` уже загруженных статей для проверки дублей.
3. Из Sapphire постранично читаются записи через `GET /publications` с параметрами `limit` и `offset`.
4. DOI статьи нормализуется и проверяется по существующим чанкам. Если статья уже есть в RAG, она пропускается.
5. Проверяется `is_open_access`. Если значение не равно `true`, статья пропускается.
6. Проверяется наличие корректного `openalex_id`. Если его нет, статья пропускается; иначе запрашивается `GET /crawler/openalex/works/{openalex_id}`.
7. Из ответа извлекаются предварительные `domain` и `field`. Если классификация отсутствует, фиксируется ошибка статьи. Если DOI ещё не известен, он берётся из ответа и повторно проверяется на дубли.
8. Собираются PDF-ссылки из записи Sapphire и доступных локаций OpenAlex. Ссылки проверяются по очереди: HTTP-статус, размер файла и сигнатура PDF. Если пригодного PDF нет, статья пропускается.
9. PDF скачивается в память, вычисляется `article_id = MD5(pdf)`. Если такой идентификатор уже есть в Chroma, статья пропускается.
10. PDF сохраняется в `S3_PUBLIC_BUCKET` по ключу `articles/{domain}/{article_id}/paper.pdf`.
11. Запускается обработка через оригинальные этапы `papers_processing_refactoring`. Используются сохранённые состояния этапов для возобновления незавершённой обработки.
12. `FetchStep` читает PDF из S3 и сохраняет рабочую копию в `S3_ETL_BUCKET`.
13. `ParseStep` преобразует PDF в HTML и изображения через Marker.
14. `HtmlCleaningStep` очищает HTML.
15. `ImageFilteringStep` фильтрует изображения и извлекает таблицы.
16. `ImageCaptioningStep` создаёт текстовые описания изображений.
17. `MetadataExtractionStep` извлекает название статьи, год, авторов и источник. Готовый DOI Sapphire используется напрямую; поиск DOI по названию и году выполняется только при его отсутствии.
18. Определяются итоговые `domain`, `field` и источник публикации через OpenAlex. Если классификация не получена, используется LLM по содержимому статьи. Суммаризация не выполняется.
19. `ChunkingStep` создаёт чанки `body` и `image_caption`. Чанки `summary` не создаются.
20. `EmbeddingStep` вычисляет векторы чанков.
21. `PublishStep` записывает чанки и векторы в Chroma. В метаданные попадают только `article_id`, `role`, `domain`, `field`, `modality`, `paper_title`, `publication_year`, `authors`, `source`, `doi`, а также `imgs_in_chunk` для текста или `image_id` для описания изображения. Служебные поля Sapphire в чанки не добавляются.
22. В `S3_PUBLIC_BUCKET` публикуются PDF, HTML, изображения и `meta.json` со служебными данными статьи. Используется итоговый `domain`; если он отличается от предварительного, ранее загруженная копия PDF остаётся в прежнем каталоге.
23. После успешной публикации удаляются промежуточные ETL-артефакты и проверяется наличие чанков статьи в Chroma. DOI и `article_id` добавляются в наборы проверки дублей текущего запуска.
24. Пайплайн переходит к следующей статье. Ошибка отдельной статьи фиксируется и не останавливает остальные; ошибка чтения страницы Sapphire прерывает проход.
25. Обработка завершается при пустой странице или достижении `--max-articles`, если он задан. Выводятся количество просмотренных и загруженных статей, причины пропусков и число ошибок.
